# 0105 — Auth: Argon2, a JWT in an httpOnly cookie, and a typed client

**Status:** Accepted · 2026-10-18

## Context

Users must register, log in, log out, and read their own profile. The
frontend (localhost:3000) and the backend (localhost:8000) are different origins.

## Decision

- **Passwords:** pwdlib with Argon2, the current OWASP recommendation.
- **Session:** a JWT (PyJWT, HS256) with the user ID as `sub`, valid for
  `JWT_EXPIRES_MINUTES` (default 60). `POST /auth/login` sets it in an
  httpOnly cookie, `session`, with `SameSite=Lax` and `Path=/`. JavaScript
  cannot read it. `Secure` is a setting: off for local development.
- **Secret:** `JWT_SECRET` from the environment. Compose sets a
  development-only value. A deployment sets its own.
- **CORS:** `app/main.py` allows the origins in `CORS_ORIGINS` with credentials.
- **Errors:** a wrong email and a wrong password give the same 401 message,
  so the response does not tell an attacker which emails exist.
- **Frontend client:** `src/lib/api.ts` (architect-owned) is one openapi-fetch
  client, typed from the contract, with `credentials: "include"`. Agents call
  `api.POST("/auth/login", { body })`. The architect does not write a client
  function for each endpoint.
- **`x-planned: true`** in the contract marks an operation that is not built
  yet. `check:contracts` allows it to be missing, so `main` stays green
  between the contract PR and the feature PR.

## Consequences

- The frontend never handles the token. `GET /auth/me` tells it who is logged in.
- No refresh token and no password reset yet. Both are later features.
- After the auth PR is merged, the architect removes the `x-planned` flags.
